Market Miam Test Map

Every automated test in the monorepo, grouped by the bounded context it protects, then by kind of test, then by the app it lives in. Blocks are sized by test count. Click a header to zoom in, a file to list its tests, and a test to read its code.

Contexts. Market Days and Ordering are the bounded contexts (ADRs 0004, 0048, 0066). Groups tagged supporting are what every context leans on; Cross-cutting holds app shells, tooling and tests that span contexts. A test's context is the directory it sits in.

Kinds, read from what a test drives. Unit: in-process, against fakes or in-memory adapters — in the packages suite these are sociable, driven through use cases. Component: a frontend component rendered and driven through its page object. Integration: across real I/O — Postgres in Docker (.container.spec.ts), a local server, or the Auth0 test tenant (.tenant.ts, run by hand). API: the api booted in memory and called over HTTP. E2E: the production app on real Postgres through a whole lifecycle (.scenario.ts, nightly).

Colour marks the app's layer: backend APIs (NestJS apps), frontends (Angular apps), and the shared-packages suite under test/ that covers the domain libraries.

Parameterised it.each tables count as one test. Shared contract suites are expanded once per implementation that runs them. Click a test to read its code, with everything else in its file folded away; Real, Through and Stand-ins are read from the file's imports by the repo's naming, a reading aid rather than a proof.
