The system's behaviour as an event model: vertical slices of commands, events, read models and automations on a timeline, derived from the packages test suite and the domain package's declared seams. Click any card for the slice's specifications — its Given/When/Then lines are the it titles of its spec file.

Slices run left to right in the order the system's own tests presuppose: a slice sits after every slice whose events appear in its Givens. Events sit on the stream (aggregate) lane they are appended to. Solid arrows carry events — from the command that appends one to the read models and automations that consume it; dashed arrows are commands dispatched by automations.

Nothing here is hand-maintained. Slices and their specifications come from test/src/market-days; event-to-stream lanes from the event declarations in packages/market-days; read-model and automation wiring from each projection's handler map and each processor's eventTypes(); actors from the API controllers.
